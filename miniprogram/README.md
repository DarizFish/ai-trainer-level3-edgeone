# 训练师备考微信小程序

原生微信小程序：900 道理论题、190 题限时模考、40 道实操填空、邮箱账号及理论记录同步。需要运行代码时，页面通过文字说明在电脑访问 www.aitrainer3.xyz 并找到同一题号。

产品范围见 [方案快照](docs/MINIPROGRAM-PLAN-2026-10-03.md)。实操填写只存本机；访客与账号分别保存。模考保留最近 10 份完整试卷供本机复盘，云端返回最近 100 条成绩摘要。

已验证范围与发布前未验收项目见 [验收记录](docs/ACCEPTANCE.md)。

分享、网站视觉统一、就地答案对比与网页实操入口的范围和验收口径见 [体验需求](docs/UX-REQUIREMENTS.md)。

## 页面交互

- 理论：判断、单选、多选分别显示已答、答对、待订正数量，并各自记住续练位置。重进已答题时恢复上次选择、对错与解析；点“重新作答”后可重练，提交新答案才更新记录。单选和判断点选后显示解析，多选确认后显示；收藏、上一题和下一题固定在底部。
- 实操目录：按 8 个模块进入，每个模块 5 题；支持题号搜索和继续上次实操，返回模块目录时恢复浏览位置。
- 代码题：阅读区使用屏幕剩余高度，长行默认换行，也可横向查看。点击空位直接在原处输入；题目、目录和参考按需打开。键盘出现时收起顶部工具栏，为上下文留出空间。
- 分析题：按报告章节阅读，点击后进入整屏写作，可展开题目边看边写；培训和指导题直接在原文下划线处输入。
- 续写与复习：代码、报告分别记住填写项与滚动位置；查看参考答案不会改变正在填写的项目。目录可筛选未填项、需练习项。草稿沿用原有账号、题号、练习版本与字段编号。

## 开发

本目录是主仓库下的独立 npm 包，使用 CommonJS；网站与小程序共用 Git 历史。微信开发者工具直接打开 `miniprogram/`，正式 AppID 和打包规则以 `project.config.json` 为准。运行代码没有 npm 依赖；以下依赖只用于本机验收。

```powershell
# 在仓库根目录安装网站依赖，再安装小程序验收依赖
npm.cmd ci
npm.cmd --prefix miniprogram ci
npm.cmd run test:miniprogram

# 或在 miniprogram/ 中运行
npm.cmd test
```

`config.js` 默认请求正式网站。题库内置一份完整内容，联网时按清单校验更新。网站已发布内容清单、提交去重迁移及接口；网络不可用时，小程序保留本机记录并显示待同步状态。

`project.private.config.json`、本机配置、密钥、依赖和临时验收输出不入库。验收脚本在缺少私有配置时使用默认设置。原独立目录留作迁移备份，后续仅修改本仓库中的源码。

## 同步题库

在仓库根目录先运行 `node scripts/generate-public-content.mjs` 和 `npm.cmd run content:miniprogram:audit`，再运行：

```powershell
npm.cmd run content:miniprogram:sync
```

也可在本目录运行 `npm.cmd run content:sync`，默认从父目录网站生成；传入 `-- <网站目录>` 可覆盖来源。不要手工修改 `data/bundled.js` 或 `data/practical-context.js`。同一次同步会生成题库和完整原始代码、文书类型；空位、参考答案与评分点均来源于网站实体层。完整代码随小程序包更新，仅在练习版本匹配时使用；线上题库版本变化且本机没有对应代码时，页面提示更新小程序，不套用旧代码。题目变化后保留旧版草稿，供用户只读查看。

## 隔离验收

终端一：

```powershell
npm.cmd run dev:api
```

在本目录执行。它在本机启动内存 PGlite，应用真实 Drizzle 迁移，启动父目录网站的 Next API。端口为 `127.0.0.1:55432`（测试数据库）和 `127.0.0.1:3210`（API）。测试账号不写入生产库。可通过脚本参数指定其他网站目录。运行前需安装根目录与本目录的依赖。

终端二：

```powershell
npm.cmd run test:api
npm.cmd run test:devtools
```

开发者工具验收复制当前运行代码到临时项目，使用独立自动化端口，允许访问本机 HTTP。原项目的合法域名校验配置保持不变。它验证原生页面输入与点击、账号接口，以及退出页面再进入时的草稿和试卷恢复；手机网络、系统后台回收和正式域名仍须真机验证。

`npm.cmd run test:experience` 验证本轮视觉与交互：首屏网站入口、题内网页指引、所有空位一键对比、紧凑参考条、长答案直接显示、notebook 浅色代码区、填写恢复以及公开分享路径，并输出截图到系统临时目录的 `aitrainer-miniprogram-acceptance/experience-review/`。剪贴板 API 在该流程中模拟，真实调用参数由客户端测试核对；实际发送与接收小程序卡片仍需真机验收。每次验收自动分配空闲端口，体验验收还核对临时项目中的源码标记，避免误验旧预览。

`node scripts/run-devtools.cjs --theory-only` 单独验证三种题型的进度、续练、历史答案、重新作答和错题订正，并输出截图。该流程使用访客本机记录，无需启动测试 API；不覆盖账号接口、实操或关闭整个应用后的恢复。

`npm.cmd run test:devtools:restart` 单独检查关闭整个测试项目再打开后的存储。当前工具环境会连普通 `wx` 存储标记一起清空，诊断结果为“无法判定”，退出码为 2；这不计入通过项。该命令只操作临时项目。实机关闭重开后的恢复必须另行验收。

默认验收不调用桌面截图接口。需要截图时在 PowerShell 设置 `$env:CAPTURE_DEVTOOLS = '1'`；输出在系统临时目录的 `aitrainer-miniprogram-acceptance` 下。该环境变量只影响验收脚本。

## 发布前

1. 用 iOS、Android 验证 Cookie 会话、退出、断网补传、后台计时和本机存储。
2. 核对微信后台的请求域名、类目、备案和隐私配置。
3. 测试通过后提交代码，记录上传版本号与 Git commit；在开发者工具上传、后台提交审核，审核通过后发布。Git 提交本身不会执行微信发布。

代码版本由 `package.json` 记录，正式 AppID 以 `project.config.json` 为准。每次上传在 [版本记录](docs/RELEASES.md) 中关联已提交的源码、内容基线和验证结果；正式发布后在对应源码提交上添加 `miniprogram-v<版本号>` 标签。平台审核及线上状态以微信后台为准，迁入 Git 不代表重新上传或发布。验证范围见 [验收记录](docs/ACCEPTANCE.md)。
