# 微信小程序最终方案快照

日期：2026-10-03 · 版本：1.0

本文固化本次讨论的产品范围与推荐实现方案，供后续开发使用。当前仅完成代码分析与方案整理，业务功能尚未实现。用户已确认的要求与推荐设计分别标明；本文不代表功能验收或发布授权。

## 1. 产品定位与范围

**原生微信小程序承担理论刷题、模拟考试和实操填空；网站继续提供完整 Python 实验环境。**

### 用户已确认

- 小程序为个人主体。
- 实操在小程序中做成普通填空练习。
- 需要运行代码时，只通过文字说明用户可以到网站执行。
- 网页执行衔接仅限上述说明；不实现自动跳转、扫码接续、填空导入网页或 Notebook 生成。

### 本快照采用的推荐设计

- 小程序使用 WXML、WXSS、JavaScript，复用现有网站后端。
- 两端共用邮箱密码账号；首版不接入微信快捷登录。
- 登录后的理论作答、错题、收藏和模考成绩通过现有后端同步。
- 实操填空草稿只保存在当前设备，首版不做实操草稿云端同步。
- 题库统一在网站仓库维护，由构建脚本生成小程序需要的数据。

## 2. 首版功能

底部导航：**学习 / 模考 / 实操 / 我的**。

| 模块 | 首版交付 |
| --- | --- |
| 学习 | 900 道理论题；分类、顺序练习、答案解析、错题与收藏；恢复当前设备练习位置 |
| 模考 | 标准卷与随机卷；190 题、90 分钟、100 分、60 分及格；本机中断恢复、成绩与复盘 |
| 实操 | 40 道题；查看题干与必要素材摘要、分步填写、参考答案、逐项核对、本地草稿 |
| 我的 | 邮箱注册与登录、退出、云端理论学习统计和成绩、同步状态、隐私说明 |

理论模考沿用现有规则：判断题 40 道，每题 0.5 分；单选题 140 道，每题 0.5 分；多选题 10 道，每题 1 分。未完成试卷保存在当前设备；跨设备同步指已保存的学习记录和成绩，不包含正在进行的试卷。

首版不包含实操模拟考试、代码执行、AI 自动批改、微信快捷登录、支付或赞赏。

## 3. 实操填空

| 题目类型 | 数量 | 改造方式 |
| --- | ---: | --- |
| 培训／指导模板题（4.1、4.2） | 10 | 复用现有每题 5 个填写项与参考答案 |
| Python 题（1.1、2.1、2.2、3.2） | 20 | 显示原始代码上下文，将已有占位转换为输入框 |
| 分析／优化题（1.2、3.1） | 10 | 按评分点整理问题、原因、措施、预期效果等填写项 |

每个填写项包含稳定编号、原题编号、上下文、参考答案及对应评分点；代码填写项额外记录所属代码单元。提取脚本可以生成候选，发布前必须逐题核对，不能假定原始模板与参考代码完全一一对应。

明确的函数名、参数等短答案按已审核答案集合核对；长代码和分析题展示参考答案、评分要点并允许自评。未匹配参考答案不直接宣称语义错误。填写完成度与运行正确性分别表达。

草稿按“访客或账号＋题号＋练习版本”隔离。输入后保存，重启后恢复；内容版本变化时保留旧草稿，并避免把旧答案套入已变化的空位。界面明确提示“仅保存在本机”，清理小程序数据或更换设备可能丢失。

实操页面统一显示说明，例如：

> 如需运行代码，请在电脑浏览器访问 www.aitrainer3.xyz，在实操题库中找到本题进行练习。

本说明不要求网站增加任何页面或交接接口。

## 4. 账号与学习记录

### 用户流程

- 已有网站账号：输入同一邮箱和密码登录小程序。
- 新用户：通过小程序调用现有注册接口，账号也能登录网站。
- 访客：允许浏览和本地练习；云端同步需要登录。
- 网站和小程序各自持有会话。用户在电脑网页上单独登录，按同一账号读取数据。
- 退出小程序撤销本次会话；切换账号后，本地草稿和待同步记录仍按各自所有者隔离。
- 访客数据不自动归入任一账号；首版保留独立访客数据，暂不实现访客记录合并。

### 推荐实现

先复用 `/api/auth/login`、`/api/auth/register`、`/api/auth/me`、`/api/auth/logout`。

小程序统一请求模块提取登录响应中的会话 Cookie，只保存所需会话值，并且只向本站 HTTPS API 发送。密码不持久化，凭证不放入链接或日志。会话过期后暂停该账号的补传并提示重新登录；网络故障与会话失效分开处理。

**待真机验证**：iOS、Android 上 Cookie 的读取、发送、持久化、失效和退出行为。新增 Bearer 令牌接口作为适配失败时的备选，不预先重做账号体系。

微信绑定与快捷登录列为后续事项。届时由服务端交换登录 code，通过绑定关系关联已有账号；绑定时验证网站账号，避免产生两套学习记录。首版不新增微信身份表。

当前代码未提供密码找回接口。邮件重置密码是正式开放注册前建议补齐的独立账号改进，需要邮件发送服务及相应后端流程，不计入本次小程序最小接入范围。

## 5. 内容与同步设计

### 统一内容来源

网站实际从 `data/entities/` 读取题库，现有脚本生成公开 JSON。扩展该流程，增加小程序实操填空数据，并提供稳定清单接口：

```text
GET /api/content/manifest  （计划新增）
```

清单包含接口结构版本、内容版本、内容哈希及下载地址。小程序按需下载、缓存和校验；更新成功后再切换到新版，下载失败继续使用完整旧缓存。地址失效时重新获取清单，不把某个带哈希的文件地址固定在小程序代码里。

练习与试卷保存内容标识。服务端仍负责最终计分；如果内容版本不兼容，应提示重新加载或保留本地记录，不能把旧题答案静默按新题判分。

### 理论记录同步

复用现有业务接口：

| 接口 | 用途 |
| --- | --- |
| `/api/theory/state` | 读取已答、错题和收藏状态 |
| `/api/theory/answer` | 保存理论作答 |
| `/api/theory/attempt` | 保存模考成绩 |
| `/api/favorites` | 收藏管理 |
| `/api/progress` | 学习统计 |

推荐首版支持登录用户弱网补传：先落本地队列，服务端确认成功后再移除，明确显示待同步状态。

现有答题接口会累加次数，模考接口会新增成绩。实现自动补传前，必须增加按账号隔离的提交编号与持久化去重：同一提交重试返回同一结果，业务写入与去重记录保持事务一致；收藏按最终目标状态同步。旧版网页请求仍保持兼容。

模考使用绝对截止时间；切到后台、重新进入或重启后重新计算剩余时间。保存题目顺序和作答，避免恢复时重新组卷。

## 6. 现有网站的改动清单

| 位置 | 范围 |
| --- | --- |
| 内容生成脚本 | 新增实操填空产物及校验 |
| 公共 API | 新增题库清单，确定内容版本兼容规则 |
| 理论作答和模考 API | 为小程序补传增加提交去重；保留现有网页行为 |
| 数据库 | 仅按去重方案新增必要结构，通过网站现有 Drizzle 迁移流程管理 |
| 登录相关 API | 优先复用现有 Cookie 会话；真机验证后决定是否需要小幅适配 |
| 网站学习页面与 JupyterLite | 本方案无需改动 |
| 实操草稿接口与表 | 首版不接入、不修改；小程序填空只保存本地 |

小程序只访问网站 API 和公开内容资源。数据库连接与密码校验仍由网站服务端处理。

## 7. 实施顺序与验收

1. **验证关键适配**：真机跑通注册、登录、会话恢复、退出；获取题库清单；实现一道理论题，以及 `4.1.1`、`2.1.1`、`1.2.1` 三类实操样题。
2. **完成理论闭环**：题库、收藏、错题、模考、学习统计；补传去重及内容版本兼容。
3. **完成全部实操填空**：40 道题的填写项和参考答案校验、本地恢复、执行说明。
4. **发布准备**：真机弱网、切后台与重启、账号切换、旧版接口兼容、隐私说明和后台配置。

核心验收标准：

- 同一账号的网站与小程序能读取一致的已同步理论记录。
- 重复补传不会增加重复成绩或重复答题次数，账号之间不串数据。
- 190 题模考按原规则评分，后台停留后倒计时正确，本机恢复不重新组卷。
- 40 道实操的填写项、参考答案和评分点可追溯；本地填写重启后仍在。
- 小程序不加载 Python 内核；执行说明能清楚告诉用户在哪里找到相同题目。
- 填空数据和题库升级不会静默丢弃或错配用户答案。

修改网站代码后遵循网站 `AGENTS.md` 的现有测试门禁。发布与数据库迁移按该仓库流程执行，实际部署需另获授权。

**工作量估计**：一名熟悉项目的开发者约 12–19 人日，不含邮件找回密码、备案与审核等待。该估计基于取消网页交接及实操云端草稿后的范围；主要不确定项为实操逐空核对和真机会话适配。
