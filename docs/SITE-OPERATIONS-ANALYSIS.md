## 1. 目标与结论

本轮需求包含五项功能：网站公告、考试报名攻略、备用网址、页脚备案信息、打赏。它们不应被设计成五个平级栏目，而应共同补齐“找到考试—完成报名—进入备考—信任本站—故障时仍可访问—自愿支持维护”的站外到站内链路。

建议的信息架构如下：

| 功能 | 产品角色 | 建议入口 | 优先级 |
| --- | --- | --- | --- |
| 备案信息 | 合规与信任基础 | 全站页脚常驻 | P0 |
| 考试报名攻略 | 从报考意图进入备考的核心路径 | 主导航，用“报名攻略”替换现有“参考资料” | P1 |
| 网站公告 | 把少量重要变化送到对应行动路径 | 首页单条公告位；必要时设历史页 | P1，与报名攻略一起实现 |
| 备用网址 | 主站不可用时的灾备入口 | 页脚“访问与备用网址”页、独立状态页或外部可信渠道 | P1，基础设施验收后才公开 |
| 打赏 | 用户自愿支持内容与服务器维护 | 页脚“支持本站”入口 | P2 |

核心产品决策：

1. 公告和报名攻略不复制官方通知，不长期维护日期、地址、收费等易变化信息；本站只给出用户下一步要做什么，并保留官方核验入口。
2. 报名攻略采用任务清单，不写成长篇政策文章，也不承诺用户具备报名资格。
3. 备用网址不是简单展示一个服务器 IP。只有域名、HTTPS、版本一致性和关键业务验收完成后才能对外称为备用网址。
4. 打赏首版采用无账号、无订单、无权益、无支付回调的自愿赞赏模式，不建设交易系统。

## 3. 统一设计原则

### 3.1 内容分层

- **本站说明**：稳定路径、操作步骤、风险提示和备考入口，可以由本站维护。
- **社区经验**：用于理解用户语言和易错点，只提炼问题，不作为资格、费用、日期的事实来源。
- **官方核验**：报名资格、时间、地点、材料原件要求、收费、考试安排均由用户在官方页面最终确认。

页面应清楚标注三者，不使用“官方攻略”“官方报名入口”等可能让用户误解本站身份的表述。

### 3.2 低干扰

- 不用全屏弹窗、连续 toast、跑马灯或自动展开二维码。
- 公告最多在首页显示一条最高优先级信息。
- 打赏不出现在答题中、计时考场、交卷确认或成绩不理想的情境中。
- 页脚备案和备用网址保持可见但不抢占学习主流程。

### 3.3 最小数据

- 报名攻略不收集姓名、身份证、社保、学历、手机号等报名材料。
- 打赏首版不收集打赏者姓名、金额、留言或支付凭证。
- 公告已读状态若需要，只使用当前浏览器保存公告 ID，不写入账号数据库。

## 4. 网站公告

### 4.1 用户问题

用户进入备考站时，可能需要知道一个会改变当前行动的重要变化，例如报名路径变化、站点维护、题库版本升级或 Lab 故障。现有网站没有统一触达位置。

公告的目标是让用户完成下一步，不是把外部通知全文搬到本站。

### 4.2 核心路径

```text
看到一句变化提示
  → 判断“是否影响我”
  → 点击唯一行动按钮
  → 进入报名攻略、站内说明或外部核验页
  → 完成行动或返回备考
```

例：公告只表达“近期报名安排有更新，请先查看报名路径并到发布方核验”，按钮为“查看报名步骤”。不要在公告中复制日期、地点、材料清单和长篇原文。

### 4.3 公告类型

| 类型 | 用途 | 默认行动 |
| --- | --- | --- |
| 报名提示 | 提醒用户报名相关信息出现变化 | 进入报名攻略 |
| 服务状态 | 维护、故障、功能降级 | 查看站内说明或备用网址 |
| 内容更新 | 指导手册、题库、评分或功能有重要更新 | 查看更新说明或对应题库 |

普通页面微调、错别字修复和后台发布不进入公告。

### 4.4 展示规则

- 首页主视觉与第一段学习路径之间放置一条紧凑公告；移动端不得横向滚动。
- 同一时间最多展示一条，通过 `priority` 决定。
- 支持开始与结束时间；过期公告自动从首页消失。
- 用户可关闭非紧急公告；关闭状态按公告 ID 保存在本地。新的公告 ID 必须重新显示。
- 只有存在多条需要追溯的公告时才建设 `/notices`。首版可以没有公告历史页。
- 公告 CTA 只能有一个主行动，外部链接必须明确标注“前往外部页面”。

### 4.5 最小内容模型

```ts
type Notice = {
  id: string;
  kind: "registration" | "service" | "content";
  title: string;
  summary: string;
  priority: "normal" | "important" | "urgent";
  startsAt: string;
  endsAt?: string;
  action: { label: string; href: string; external?: boolean };
};
```

首版建议使用版本化 TypeScript/JSON 文件，不建数据库或后台 CMS。只有运营频率高到代码发布明显阻碍时，再评估后台。

### 4.6 验收标准

- 无有效公告时页面不留空白占位。
- 有多条公告时只展示有效期内最高优先级的一条。
- 文案不包含复制的外部通知正文，不声称本站是报名或认定机构。
- 关闭公告后当前浏览器不重复展示；新公告仍能出现。
- CTA 能把用户带到唯一下一步；外部链接新窗口打开并带安全属性。

## 5. 考试报名攻略

### 5.1 产品定位

报名攻略解决的是“我接下来按什么顺序做”，而不是“本站替我判断资格或提供一份不会变化的政策副本”。

主导航把“参考资料”改成“报名攻略”，继续复用 `/resources` 或迁移到更语义化的 `/registration`；如果改路由，旧 `/resources` 应永久重定向，避免已有收藏失效。

### 5.2 核心路径

```text
确认报考目标并自查申报路径
  → 找到本期报名信息发布方并核验
  → 按本期要求准备材料
  → 完成报名与费用确认
  → 保存成功凭证，等待准考证并核对考试安排
  → 回到本站开始理论与实操备考
```

页面不要展示一个长期存在的“立即报名”按钮。只有确认存在可用外部入口时，才显示“前往发布方核验”；没有可核验场次时显示“先准备材料／开始备考”。

### 5.3 页面结构

1. **你正在准备什么**：固定说明本站服务上海地区人工智能训练师三级考生，避免用户看错地区或等级。
2. **六步报名清单**：每一步只回答“做什么、完成标志、遇到问题去哪里核验”。
3. **材料准备框架**：按身份证明、申报条件证明、报名方本期要求三组列出检查框架，不写死具体文件名称和格式。
4. **容易混淆的概念**：培训报名不等于考试报名；报名意向不等于报名成功；本站账号不等于考试账号。
5. **完成报名后的动作**：保存凭证、留意准考证、核对设备与考试材料、进入本站备考计划。
6. **核验入口**：只保留少量可信发布方链接，并展示“上次人工核验日期”；不复制其通知正文。
7. **常见问题**：来自社区调研的问题，用本站语言重新回答；涉及资格、费用或时限时只解释判断方法并引导核验。

### 5.4 每一步的内容模板

| 字段 | 作用 |
| --- | --- |
| 本步目标 | 用户为什么要做这一步 |
| 你要做什么 | 1—3 个动作 |
| 完成标志 | 用户如何知道可以进入下一步 |
| 常见卡点 | 由小红书和咨询记录归纳，不能杜撰政策 |
| 去哪里核验 | 官方／报名组织方入口 |
| 下一步 | 唯一 CTA |

### 5.5 内容维护规则

- 不在攻略正文维护具体报名日期、收费、地址和材料格式。
- 当外部信息变化时，优先更新公告的“变化提示”和核验链接，而不是重写整篇攻略。
- 所有外部入口必须有来源名称、域名和人工核验日期。
- 社区经验如果与发布方要求冲突，页面必须以“存在差异，请按本期发布方要求”为结论。
- 每季度或收到用户反馈后重新抽样社区内容；把问题模式写入 FAQ，不保存博主原文和个人信息。

### 5.6 验收标准

- 新用户能在一个页面内说清报名顺序、每一步完成标志以及报名后去哪备考。
- 页面不收集或上传任何报名材料。
- 页面不展示未经当期核验的“可报名”“报名中”或具体资格结论。
- 页面明确区分本站、培训机构、报名组织方和认定发布方。
- 从首页公告、首页上海认定信息卡、主导航均能进入同一攻略路径。

## 6. 备用网址

### 6.1 产品目标

主站因 CDN、DNS、区域网络或发布故障不可达时，为用户提供一个可验证、可记忆的第二入口。备用网址必须是同一产品的受控部署，不是第三方镜像。

备案通过降低了国内自托管域名上线的前置障碍，但不等于任意新域名已经备案，也不代表当前阿里云 IP 可以直接成为正式备用入口。

### 6.2 推荐方案

优先级从高到低：

1. **同一正式域名的 DNS／源站故障切换**：对用户最透明，Cookie 与浏览器本地数据仍保持同源。
2. **独立备用域名**：解决主域名本身不可用的问题，但用户需要重新登录，本地考试和草稿不能自动迁移。
3. **独立状态页或外部可信渠道**：告诉用户当前唯一有效的主、备用域名。状态页应与主站使用不同托管与 DNS 故障域。

仅在主站页脚写出备用网址不足以完成灾备，因为主站打不开时用户看不到。页脚入口的作用是让用户提前收藏。

### 6.3 “访问与备用网址”页面

建议路由 `/access`，内容包括：

- 当前主域名与备用域名；
- 每个域名的用途和最后验证时间；
- 防钓鱼提示：本站只认可页面列出的 HTTPS 域名；
- 切换域名后的数据连续性说明；
- 服务状态入口；
- 建议用户收藏或截图保存，不提供短链和裸 IP。

### 6.4 数据连续性边界

| 数据 | 切换到独立域名后的预期 |
| --- | --- |
| 登录状态 | 不继承，需要重新登录 |
| 账号云端理论进度、收藏、成绩 | 登录后可从共享数据库恢复 |
| 已同步的云端草稿 | 登录后可恢复，需逐类验证 |
| 进行中的理论／实操模拟考试 | 使用域名本地存储，不能自动续考 |
| 未同步的本地答题草稿 | 不能自动迁移 |
| JupyterLite 浏览器文件系统 | 不能假定跨域可见，切换前应导出成果 |

页面必须诚实展示这些边界，不能使用“无缝切换”文案。

### 6.5 对外发布门槛

- 备用域名自身的备案／接入关系已经确认；
- DNS 与 HTTPS 正常，证书自动续期；
- 使用与主站同一已验证提交和兼容数据库 schema；
- `/api/health/live` 与 `/api/health/ready` 通过；
- 登录、进度、草稿、题库、素材下载、模拟考试、JupyterLite、MIME 与缓存头完成验收；
- 主站与备用站均能展示对方地址和当前状态；
- 有域名撤销、泄露或过期时的下线流程。

未达到以上门槛时，只能称为“自托管验收环境”，不能在产品界面标作备用网址。

## 7. 页脚备案信息

### 7.1 产品要求

备案信息是全站合规与信任元素，不单独建设页面。应放在页脚最低一行，在所有公开页面、账号页、模拟考场和移动端都可访问。

### 7.2 展示规则

- 展示真实 ICP 备案号，并链接至工信部备案查询网站 `https://beian.miit.gov.cn/`。
- 若公安联网备案已经完成，再展示公安备案图标、完整编号和对应详情链接；未完成则不显示占位文案。
- 备案主体名称只有在确有展示需要且与备案信息一致时才加入，不从域名或站名推断。
- 链接新窗口打开，使用 `rel="noopener noreferrer"`。
- 备案号应是可复制文本，不只嵌在图片中。
- 备案信息在主站和备用网址保持一致；若域名对应备案信息不同，则由站点配置按域名输出，不写死错误信息。

### 7.3 配置建议

在 `lib/site.ts` 集中维护经核验的 `ICP_RECORD`、可选 `PUBLIC_SECURITY_RECORD` 与链接，避免在页脚组件散落硬编码。信息未补齐时构建或合同测试应明确失败，而不是发布“待填写”。

### 7.4 验收标准

- 桌面和 390px 移动视口均完整显示备案号，没有截断或横向滚动。
- 点击 ICP 备案号打开正确查询站。
- 代码和页面中不存在示例号、“备案中”或推断出的公安备案号。
- 主、备用域名展示的信息与各自实际备案状态一致。

## 8. 打赏／支持本站

### 8.1 产品定位

打赏是对免费内容、服务器和素材维护的自愿支持，不是购买题库、获得答案、提高成绩、加速服务或取得会员身份。

建议用户侧名称使用“支持本站”，页面内部说明“自愿赞赏”；避免“充值”“下单”“购买”“会员”等交易语义。

### 8.2 推荐首版

采用静态支持页 `/support`：

```text
页脚点击“支持本站”
  → 阅读用途与自愿说明
  → 主动展开一个收款平台的赞赏码
  → 使用平台扫码完成
  → 返回本站
```

首版不接 API、不生成订单、不查询支付结果、不建立打赏记录表。二维码作为受控静态资产维护，页面不默认自动弹出。

### 8.3 页面内容

- 一句话说明本站免费开放，赞赏用于域名、服务器和内容维护；
- “不赞赏不影响任何功能”的显著说明；
- 可选的微信／支付宝赞赏入口，平台名称和收款主体提示清晰；
- 防诈骗提示：本站不会私信索要转账、验证码或报名材料；
- 联系邮箱，用于误付等问题，但不得承诺平台能力之外的自动退款流程；
- 不显示实时打赏榜、金额目标、倒计时或诱导性默认金额。

### 8.4 产品与合规边界

- 优先使用支付平台明确支持的赞赏／收款能力，并由收款主体确认平台规则、税务和账务处理；本文不替代法律或财税意见。
- 不向打赏者提供题库权限、报名资格判断、证书、课程或一对一服务，否则需求将从赞赏转为交易，需要另做支付、订单、退款、发票和用户协议设计。
- 不上传支付截图，不收集昵称、手机号、留言和支付单号。
- 二维码图片不得包含不必要的个人资料；上线前用真实手机验证收款方名称提示符合预期。
- 隐私政策是否需要补充取决于最终方案：纯外部扫码且本站不接收任何支付数据时，只需说明跳转／扫码由第三方平台处理；若接入支付回调，则必须另做隐私、数据安全与交易合规评审。

### 8.5 入口规则

- 页脚提供“支持本站”，与法律链接、备案信息分组，不进入主导航。
- 可以在“关于本站”或内容更新说明底部出现一次轻量入口。
- 不在答题页、计时考试、交卷弹窗、成绩页首屏或错误页强提示。

### 8.6 验收标准

- 不打赏的用户不受任何功能、内容和速度限制。
- 支持页不创建本站订单或个人数据记录。
- 二维码默认不遮挡页面，移动端可以清楚识别并保存／使用。
- 文案不暗示官方身份、不与报名或考试通过挂钩。
- 支付入口下线时页面能隐藏对应平台，不留下失效二维码。

## 10. 实施顺序

### 阶段 A：低风险合规与入口整理

1. 产品负责人补齐 ICP 备案号、公安备案状态和对应链接。
2. 页脚增加备案信息。
3. 将“参考资料”产品命名调整为“报名攻略”，先完成稳定的六步路径和核验入口。

### 阶段 B：轻量运营能力

1. 增加版本化公告数据与首页单条公告位。
2. 公告 CTA 接入报名攻略、服务状态或内容更新路径。
3. 完成人工小红书样本复核，用高频问题补充 FAQ，不复制笔记。

### 阶段 C：灾备公开

1. 确认备用域名备案、DNS、HTTPS 和续费责任。
2. 对自托管副本执行完整验收。
3. 建设 `/access` 与独立状态页后才在页脚公开备用网址。

### 阶段 D：自愿赞赏

1. 确认收款主体、平台能力和二维码。
2. 建设静态 `/support` 页面与页脚入口。
3. 验证移动端扫码、防诈骗文案和隐私边界。

## 11. 不在本轮范围

- 自动抓取并全文转载官方公告；
- 自动判断用户是否具备报考资格；
- 代报名、上传报名材料或代收考试费用；
- 公告 CMS、站内信、短信、邮件或微信推送；
- 跨域迁移浏览器 localStorage、Cookie 或 JupyterLite 文件；
- 打赏订单、支付回调、打赏榜、会员权益、发票和退款系统；
- 在备案号、备用域名或收款资料缺失时使用占位数据上线。
